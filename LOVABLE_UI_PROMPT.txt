9. STATUS, TRUST AND PUBLICATION SEMANTICS

Status is operational data, not decoration. Use a consistent StatusBadge plus plain-language supporting text. Never infer trust from a green-looking card.

Critical rule: pending is not verified.

- PENDING_REVIEW means submitted to moderation. It is not approved, published or verified.
- PENDING_VERIFICATION means a dealer/profile verification is awaiting decision. It must not show a Verified badge.
- CHANGES_REQUESTED means the owner must read feedback, edit and resubmit.
- APPROVED means an admin decision has passed the review step; it does not automatically mean publicly visible unless that collection workflow makes it public.
- VERIFIED is the dealer/profile verification state that may receive explicit Verified wording.
- PUBLISHED is public for the relevant collection.
- AVAILABLE/BUSY are public worker availability states after review; Busy is still a valid public profile state.
- ACTIVE can mean an alert, campaign or entitlement is currently operating. Always qualify it by context.
- REJECTED, SUSPENDED, ARCHIVED, EXPIRED, CLOSED, SOLD_RENTED and REFUNDED need distinct, non-celebratory treatments and the next valid action when one exists.

Current public eligibility is server-controlled. The existing public endpoints expose only public-safe fields for states such as:

- properties: PUBLISHED
- dealers: VERIFIED
- materials: PUBLISHED or OUT_OF_STOCK as configured
- professionals: PUBLISHED
- jobs: PUBLISHED
- workers: AVAILABLE or BUSY
- projects: PUBLISHED
- ads: ACTIVE

Do not make pending/draft records discoverable through client filtering. Do not print “RERA verified” merely because a RERA number exists. Prefer exact copy such as “RERA number provided”, “Verification pending”, “Verified dealer”, “Published listing” or “Changes requested”.

Status colours must not be the only signal. Include icon/text, maintain contrast, and provide status explanations in a tooltip or detail row that also works on touch/keyboard.

12. REALISTIC LOADING, EMPTY, ERROR AND OFFLINE STATES

Every public directory, dashboard overview, collection, detail view, form and billing surface must have intentionally designed states:

Loading:

- Use skeletons matching final layout, not a full-page spinner.
- Preserve navigation and page title while data loads.
- Use aria-busy and non-disruptive loading announcements.

Empty:

- Explain why the area is empty and provide exactly one useful next action.
- Examples: “No saved properties yet — Explore properties”, “No listings need review”, “No eligible campaigns — Create a campaign first”, “No invoices yet — Invoices appear after a confirmed payment”.
- Do not insert sample records into authenticated workspaces.

Error:

- Use the safe server message, request context and Retry action.
- 401: sign in/session expired; 403: insufficient permission; 404: unavailable/not owned; 409: stale/duplicate/conflicting state and refresh; 422/400: field validation; 429: rate limited with respectful retry copy; 5xx: temporary service issue.
- Preserve entered form data on recoverable failure.

Offline/poor connection:

- Show an offline banner and disable actions that cannot safely complete.
- Do not claim a mutation/payment succeeded until the server confirms it.
- If status is uncertain after a payment callback, refresh the real order state.

- Works without clipping at 320px, 360px, 390px, 768px, 1024px and wide desktop layouts.

14. ACCESSIBILITY ACCEPTANCE CHECKLIST

- Meet WCAG 2.2 AA for colour contrast, focus visibility and core interactions.
- Use semantic landmarks: header, nav, main, aside and footer.
- Exactly one useful h1 per page; heading hierarchy is logical.
- All controls have programmatic names; visible labels are associated with inputs.
- Keyboard users can open/close menus, dialogs, drawers, filters and row actions; focus returns to the trigger.
- Dialogs have focus trap, labelled title/description and Escape behavior; never nest inaccessible dialogs.
- Focus order matches visual order. No keyboard trap.
- Status, errors, availability and payment state never rely on colour alone.
- Error summary links/focuses the invalid field. Server field errors remain visible until corrected.
- Loading/success/error announcements use aria-live deliberately without excessive chatter.
- Reduced-motion preference disables non-essential animation. No autoplay carousel.
- Icons used alone have aria-label/title or adjacent accessible text; decorative icons are aria-hidden.
- Locale selector announces the current language; RTL is supported for ar.
- Currency, dates and numbers are formatted for the active locale while API keys/enums remain unchanged.

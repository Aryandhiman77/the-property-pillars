# The Property Pillar data-flow map

Verification date 19 November 2026. Field constraints and permitted transitions are defined in the source files linked below. The [current verification report](CURRENT_VERIFICATION.md) separates executed evidence from source inspection and missing behavior.

## Public form pipeline

Localized App Router task pages render a shared form on the public marketplace. `listing-actions.tsx` carries the selected public record into enquiry, service and application forms. The property directory carries its city and buy/rent filters into the saved-search form. `PublicTask` opens the dedicated localized login page. The same browser tab can restore the temporary form snapshot for 25 minutes. The selected locale and record return with the validated internal URL. Uploads are excluded from that snapshot. A verified sign-in unlocks submission and uploads. The user must submit explicitly. Explicit drafts are persisted for properties and material RFQs.

The browser sends a same-origin `POST /api/v1/workspace/<collection>` with a title, optional description, collection data and, for review submissions, a permitted initial status. Client errors and server paths such as `data.items.0.quantity` bind to controls via `aria-invalid` and `aria-describedby`. A general error area displays session, transport and non-field errors. Submission stays disabled during an upload or an in-flight save. A successful response supplies the persisted record ID and status, and links to its dashboard collection. The local in-flight guard does not give arbitrary POST retries server-wide idempotency.

Express reads the signed session cookie and resolves a current database session. The collection checks tenant and creator role before parsing a strict data shape. It validates required fields, collection consistency and review readiness, derives trusted values and resolves the parent and recipient using tenant-scoped database queries. `WorkspaceItem` and a `WorkspaceEvent` are inserted in one transaction. A later `PATCH /api/v1/workspace/<collection>/<id>` checks ownership, target or admin, permitted transitions and the prior row version. `GET /api/v1/workspace` uses collection visibility and owner/recipient scopes. Admin reads are tenant-scoped. `GET /api/v1/public/<alias>` requires an eligible public status and `publicAt` and projects explicitly public fields. Guest queries use the configured non-demo public tenant.

## Public entry and persistence

Paths are below `/{locale}`. All field keys in this table live in `WorkspaceItem.data` unless noted. `qty`, money, experience and area values are numeric. Collection roles listed here are creator roles. Owners, acting recipients and administrators have separate permissions for later transitions. The verification report covers the individual browser result for each row.

| Public page and originating CTA | POST collection and key fields | Creator and saved status | Related records, reads and subsequent behavior |
| --- | --- | --- | --- |
| `/post-property` from homepage, header, mobile and property directory | `properties`. `listingIntent`, `propertyCategory`, `propertyType`, `propertyTypeOther`, `countryCode`, `postalCode`, `state`, `city`, `locality`, `addressLine`, `price`, `currency`, `areaValue`, `areaUnit`, `bedrooms`, `bathrooms`, RERA fields, `mediaUrls[]`, `consentAccepted` | Owner, dealer, builder. Draft `DRAFT` or submit `PENDING_REVIEW` | Owner and admin see private staging and review. Corrections resubmit to review. Admin can publish, and public projection excludes postal code and private address. Pause, suspension and similar states withdraw the projection. |

Requester, recipient and admin see it. Recipient can advance contact, visit, negotiation and outcome statuses. Contact details remain private. Site visit requires a future time. Browser local datetime is sent as ISO. |

Admin and owner see the record. Eligible vendors see a limited projection via matching published products, categories and cities. Quotes are children and can move RFQ to quoting, quotes received and vendor selected. |
| `/materials/add-product` from materials directory | `materialProducts`. Publication makes the allowed catalogue fields public. Published products determine RFQ eligibility. `OUT_OF_STOCK` remains public with explicit availability. |
| `/professionals/request` from directory and professional details | `serviceInquiries`. `serviceProfileId`, `serviceType`, `city`, `phone`, `message`, `consentAccepted` | Buyer, owner, dealer, builder, vendor, white-collar seeker. `NEW` | The API loads the published profile and assigns its owner. | `/professionals/register` from professional directory | `serviceProfiles`. `serviceType`, `city`, `serviceAreas[]`, `yearsExperience`, RERA and contact fields, `portfolioUrls[]`, publication and contact consent | Professional. `PENDING_REVIEW` | One non-archived profile per owner on sequential requests. | `/jobs/post` from jobs directory | `jobs`. | `/jobs/apply` from jobs directory and job details | `jobApplications`. `jobId`, scoped `resumeUrl`, `coverNote`, `phone`, `consentAccepted` | White-collar seeker. `SUBMITTED` | API resolves the published job’s employer and links the parent. | `/workers/register` from worker directory | `workerProfiles`. Trade, city, daily rate/currency, contact fields, availability, experience and consent | Blue-collar worker. `PENDING_REVIEW` | Existing email account auth and profile moderation. | `/dealers/register` from dealer directory and dealer microsite CTA | `dealerProfiles`. | `/projects/new` from projects directory | `builderProjects`. | `/finance-services/apply` from Tools menu, finance page and EMI calculator | `loanInquiries`. Admin moves through acknowledgment, investigation, reply and resolution. Related ID is stored as report metadata. No separate export/deletion workflow. |

## Management and external effects

| Management action | Data path, authorization and effects | Retry and availability |
| --- | --- | --- |
| Moderation and corrections | Dashboard edit/review modal → workspace PATCH. Admin reason is persisted as `WorkspaceEvent.metadata.reviewNote`; selected decisions appear in owner feedback and history. Status changes update `publicAt` and determine directory reads. | Conditional update against current prior status and row timestamp. Conflicts return 409. |
| Attach local images | Browser sends JPEG, PNG or WebP to `POST /api/v1/uploads` with collection and field purpose. Express requires session, validates content with Sharp and writes normalized WebP and owner/tenant/purpose metadata under the local upload root. New attachment inputs are checked again. | Owner preview is private. Published eligible parent references allow public access. Existing stored references remain usable, including older external links. New attachments require a scoped local upload. Local files and their metadata must be retained together. |
| Attach and retrieve résumé | Next streaming upload route → Express binary content validation, 10 MB maximum → tenant-private file → application create rechecks applicant ownership. The GET uses tenant-scoped application relationship for employer/admin access. | Upload failure does not create an application. Reply displays field error and permits retry. Private file reads are no-store. |
| Quote and acceptance | Vendor dashboard → `materialQuotes` referencing eligible RFQ → requester receives child record. Submit validates items, calculates total on server and progresses RFQ. Accept conditionally moves the parent and marks other active offers rejected. | Parent transition and quote update happen in the transaction. Matching vendors discover RFQs via their dashboard. BOQ upload and per-matching-vendor notifications are missing. |
| Dashboard notifications | Business event → owner or target, plus eligible tenant admin → `GET /workspace/notifications`. Dropdown asks for up to ten unread entries, history paginates. `PATCH /workspace/notifications/:id/read` creates account-scoped `WorkspaceNotificationRead`. | Repeated read is safe. Actor’s own events are excluded from their inbox. There is no durable email/WhatsApp/SMS delivery worker for business events. Registration SMTP is independent. |
| Signup and session | `POST /auth/register` creates a pending email account with hashed verification code and expiry. SMTP sends a code, `/verify-email` verifies it, verified `/sign-in` creates a persisted session and signed HTTP-only cookie. `/session` reads it and `/logout` revokes it. | Resend is cooldown-limited. Signup excludes admin. Session, role and tenant checks happen in Express. No phone OTP and no unvalidated return URL in public tasks. |
| Account profile and password | `GET/PATCH /account/profile` reads or changes the active account's `User` profile. Name, email, phone, about, location and logo are shown. Current editable data includes name, about, location and logo. `POST /account/password` verifies the current password, updates its hash and revokes other live sessions. | Logo uses the separate account upload purpose. The existing client hides the password and shows errors by field. The password change is conditional on the previous hash. |
| Payment and invoice | Billing catalog → `POST /checkouts` → local `BillingOrder` and bound Razorpay order → signed `/webhooks/razorpay` and verified provider lookup → `BillingEvent`, paid state, `BillingEntitlement`, `BillingInvoice`, PDF and order history. | Configured INR catalog, server-priced payment and tax. Provider/order replay handling, refund revocation and scoped invoice access were exercised with a controlled provider. Live Razorpay requires credentials and merchant acceptance. |
| Campaign and paid visibility | Builder approved project → `adCampaigns` → admin review and activation guard requiring an active bound entitlement → public ads API checks date window, entitlement and published parent. | Checkout success alone does not activate a campaign. Public page placement, impressions, clicks, verified leads, CTR and CPL are not implemented. |
| Search and location | Header uses a browser geolocation result or manual directory choice. Reverse lookup uses browser coordinates when permitted. India PIN resolves via the postal API. Directory filters hit the public API and text/location filters run before the result limit. | No IP-location, coordinate search/map, radius, FX or area-conversion service. Home/detail dates and search results depend on the current database rather than generated fixtures. |
